ARCHITECTURAL DECISIONS (10 files - Complete ADR Set):
12. decisions/adr-001-ddd.mdx
    - Decision: Use Domain-Driven Design with Rails + dry-rb
    - Problem: Complex multi-domain system
    - Solution: Clear separation with operations pattern
    - Consequences: More boilerplate, prevents fat models

13. decisions/adr-002-result-monad.mdx
    - Decision: Result monad for expected errors (no exceptions)
    - Rationale: Visible error paths, composable, no performance cost
    - Implementation: Success/failure with and_then chaining

14. decisions/adr-003-monorepo.mdx
    - Decision: Monorepo in Phase 1-2, extract in Phase 3+ if needed
    - Rationale: MVP speed, shared code, simple operations, clear extraction

15. decisions/adr-004-rest-api.mdx
    - Decision: REST API for Phase 1, GraphQL in Phase 3+ if needed
    - Rationale: Simplicity, caching, performance, team familiarity

16. decisions/adr-005-dry-rb.mdx
    - Decision: Use dry-rb (dry-types, dry-validation, dry-struct)
    - Rationale: Type safety, composable validation, testable

17. decisions/adr-006-event-dispatcher.mdx
    - Decision: Event dispatcher for cross-domain communication
    - Rationale: Loose coupling, easy extraction, explicit dependencies

18. decisions/adr-007-phase-1-focus.mdx
    - Decision: Phase 1 focuses on traceability graph, not heavy AI
    - Rationale: Cost control, speed, predictability, validates hypothesis

19. decisions/adr-008-open-source.mdx
    - Decision: Open-source CLI and SDKs, keep backend proprietary
    - Rationale: Adoption, network effects, community contributions

20. decisions/adr-009-design-partners.mdx
    - Decision: Design partner program (5-10 partners) over public beta
    - Rationale: High-quality feedback, fast validation, early revenue

21. decisions/adr-010-self-hosted.mdx
    - Decision: SaaS-first Phase 1, self-hosted in Phase 2, enterprise Phase 3
    - Rationale: MVP speed, clear revenue, better metrics, flexibility
