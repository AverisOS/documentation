# Common Patterns

This guide covers the most common patterns you'll use when building operations in AverisOS.

## Pattern 0: Lightweight Operation (No Side Effects)

**Use when**: Trivial CRUD, a pure read, or a field update with no cross-domain effects and no semantic validation beyond "does this record exist." This is the **default** — reach for the full four-phase pattern (Pattern 1/2) only when the operation meets 2+ of the criteria in [ADR-001](../decisions/adr-001-ddd.mdx#selective-four-phase-operations).

### Example: Update Artifact Title

```ruby
module Traceability
  module UpdateArtifactTitle
    ArtifactAndTitle = Struct.new(:artifact, :title, keyword_init: true)

    class Validate
      include Dry::Monads[:result]

      def initialize(artifact_repository:)
        @artifact_repository = artifact_repository
      end

      def call(artifact_id:, title:)
        return Failure("Title is required") if title.blank?
        return Failure("Title max 500 chars") if title.length > 500

        artifact = @artifact_repository.find(artifact_id)
        return Failure("Artifact not found") unless artifact

        Success(ArtifactAndTitle.new(artifact: artifact, title: title))
      end
    end

    class Command
      include Dry::Monads[:result]

      def call(artifact:, title:)
        artifact.update!(title: title)
        Success(artifact)
      end
    end
  end
end
```

### Example: Pure Read (Command only, no Validate needed)

```ruby
module Traceability
  module GetArtifact
    class Command
      include Dry::Monads[:result]

      def initialize(artifact_repository:)
        @artifact_repository = artifact_repository
      end

      def call(artifact_id:)
        artifact = @artifact_repository.find(artifact_id)
        return Failure("Artifact not found") unless artifact
        Success(artifact)
      end
    end
  end
end
```

If you find yourself adding a second DB-dependent check or a cross-domain event to one of these, that's the signal to graduate it to Pattern 1 or 2 below.

## Pattern 1: Operation with Simple Validation

**Use when**: A critical-path operation (e.g. registration, auth) that's still relatively simple — full four phases because it meets the "critical path" criterion in [ADR-001](../decisions/adr-001-ddd.mdx#selective-four-phase-operations), even though the validation itself is minimal. For non-critical simple CRUD, prefer [Pattern 0](#pattern-0-lightweight-operation-no-side-effects) instead.

### File Structure
```
domains/authentication/domain/
├── authentication_service.rb
├── register_user/
│   ├── request.rb
│   ├── request_factory.rb
│   ├── verify.rb
│   ├── validate.rb
│   └── command.rb
```

### Implementation

See `backend/domains/authentication/domain/register_user/` for the full,
current implementation. Password hashing is delegated to Devise
(`database_authenticatable`), not called directly, and `Verify`/`Validate`
are `Dry::Validation::Contract`s per [ADR-005](../decisions/adr-005-dry-rb.mdx)
rather than hand-rolled checks.

**Request** (input struct — normalization and derived values live here so
every phase reasons about the same value):
```ruby
module Authentication
  module RegisterUser
    class Request
      attr_reader :email, :password, :organization_name

      def initialize(email:, password:, organization_name:)
        @email = email
        @password = password
        @organization_name = organization_name
      end

      # Devise is configured with case_insensitive_keys/strip_whitespace_keys
      # for :email, so every lookup here has to normalize the same way or
      # Validate would wave through "A@Example.com" when "a@example.com"
      # already exists.
      def normalized_email
        email.to_s.strip.downcase
      end

      def organization_slug
        organization_name.to_s.parameterize
      end
    end
  end
end
```

**RequestFactory** (translates raw params into the typed Request):

Callers — controllers, console scripts, background jobs — never build a
`Request` by hand. `RequestFactory.build` takes **explicit keyword
arguments** matching the `Request`'s own keywords, never a raw
`params`/hash blob, so a typo raises `ArgumentError` instead of silently
producing `nil`:

```ruby
module Authentication
  module RegisterUser
    class RequestFactory
      def self.build(email:, password:, organization_name:)
        Request.new(email: email, password: password, organization_name: organization_name)
      end
    end
  end
end
```

**Verify** (format validation, no DB) — a `Dry::Validation::Contract`:
```ruby
module Authentication
  module RegisterUser
    class Verify < Dry::Validation::Contract
      extend Dry::Monads[:result]

      params do
        optional(:email).maybe(:string)
        optional(:password).maybe(:string)
        optional(:organization_name).maybe(:string)
      end

      rule(:password) do
        key.failure("Password is required") if value.blank?
        key.failure("Password must be 8+ characters") if value.present? && value.length < 8
      end

      # ... email/organization_name rules follow the same shape

      def self.call(request)
        result = new.call(email: request.email, password: request.password, organization_name: request.organization_name)
        return Success(request) if result.success?
        Failure(result.errors.to_a.first.text)
      end
    end
  end
end
```

**Validate** (semantic validation, with DB) — also a `Contract`, since
`Dry::Validation` handles both schema-shape and DB-backed rules:

`AverisOS::BaseCommand` (below) dispatches to `Verify` and `Validate`
identically — both need a class-level `.call(request)`. `Contract#call` is
an instance method, so add a thin `self.call` delegator matching `Verify`'s
shape:

```ruby
module Authentication
  module RegisterUser
    class Validate < Dry::Validation::Contract
      include Dry::Monads[:result]
      include AverisOS::Deps["repositories.user", "repositories.organization"]

      params do
        required(:normalized_email).filled(:string)
        required(:organization_slug).filled(:string)
      end

      rule(:normalized_email) do
        key.failure("Email already registered") if user_repository.exists?(email: value)
      end

      rule(:organization_slug) do
        key.failure("Organization name is already taken") if organization_repository.exists?(slug: value)
      end

      def call(request)
        result = super(normalized_email: request.normalized_email, organization_slug: request.organization_slug)
        return Success(request) if result.success?
        Failure(result.errors.to_a.first.text)
      end

      # Convention entry point AverisOS::BaseCommand dispatches to
      # (matches Verify's self.call).
      def self.call(request)
        new.call(request)
      end
    end
  end
end
```

**Command** (execute operation) — subclasses `AverisOS::BaseCommand`:

`AverisOS::BaseCommand` (`app/lib/averis_os/base_command.rb`) owns the
`Verify -> Validate -> perform` orchestration: it resolves the sibling
`Verify` and `Validate` classes by naming convention (same namespace as the
`Command`), runs them in order via `Dry::Monads` `.bind`, and only calls
`perform` if both succeed. `Verify` is **required** — `BaseCommand` raises
`NameError` if a command has no sibling `Verify`. `Validate` is
**optional** — a command with no DB-dependent checks simply has no sibling
`Validate` class, and `BaseCommand` skips it rather than erroring.
Subclasses implement `perform(request)`, never `call` — `BaseCommand#call`
is the only thing allowed to invoke `perform`, and `perform` is
automatically re-protected on every subclass (a `method_added` hook), so
external callers can't bypass `Verify`/`Validate` by calling it directly.

```ruby
module Authentication
  module RegisterUser
    Registered = Struct.new(:user, :organization, keyword_init: true)

    class Command < AverisOS::BaseCommand
      include AverisOS::Deps[
        user_repository: "repositories.user",
        organization_repository: "repositories.organization",
        organization_membership_repository: "repositories.organization_membership",
        event_dispatcher: "services.event_dispatcher"
      ]

      def perform(request)
        user = nil
        organization = nil

        ActiveRecord::Base.transaction do
          organization = @organization_repository.create!(
            name: request.organization_name,
            slug: request.organization_slug
          )

          user = @user_repository.create!(
            email: request.normalized_email,
            password: request.password,
            password_confirmation: request.password
          )

          @organization_membership_repository.create!(
            organization: organization,
            user: user,
            role: "owner"
          )
        end

        @event_dispatcher.dispatch(UserRegistered.new(user_id: user.id, organization_id: organization.id))
        Success(Registered.new(user: user, organization: organization))
      rescue ActiveRecord::RecordInvalid => e
        # Validate pre-checks email and slug availability, but two concurrent
        # registrations of the same email/organization name can still race
        # past it. Translate the model-level failure into the same Result
        # shape everything else returns so callers render 422, never a 500.
        Failure(e.record.errors.full_messages.join(", "))
      end
    end
  end
end
```

Callers never see `Verify`/`Validate` at all — the public interface stays
`Command.new.call(request)`, exactly like a command with no `BaseCommand`:

```ruby
Authentication::RegisterUser::Command.new.call(request)
# runs Verify.call -> Validate.call -> perform, short-circuiting on the
# first Failure; returns whatever perform returned on success.
```

## Pattern 2: Operation with Complex Business Logic

**Use when**: Multiple checks, side effects, cross-domain concerns.

### Example: Link Artifacts with Circular Dependency Detection

**Verify** (format validation):
```ruby
module Traceability
  module LinkArtifacts
    class Verify
      extend Dry::Monads[:result]

      def self.call(request)
        # 1. Check IDs are provided
        return Failure("Source artifact ID is required") if request.source_id.blank?
        return Failure("Target artifact ID is required") if request.target_id.blank?

        # 2. Check they're not the same
        if request.source_id == request.target_id
          return Failure("Cannot link artifact to itself")
        end

        # 3. Check relationship type is valid
        valid_types = %w[implements validates depends_on related_to]
        unless valid_types.include?(request.relationship_type)
          return Failure("Invalid relationship type")
        end

        Success(request)
      end
    end
  end
end
```

**Validate** (semantic validation with prefetching):

dry-monads' `Success`/`Failure` each carry exactly one payload — there's no `data:`
side-channel for passing extra prefetched records forward. When a later phase needs
records this phase already looked up (here: the `source`/`target` artifacts, so
`Command` doesn't re-fetch them), bundle everything the next phase needs into a small
`Struct` and return *that* as the single `Success` value:

```ruby
module Traceability
  module LinkArtifacts
    LinkContext = Struct.new(:request, :source, :target, keyword_init: true)

    class Validate
      include Dry::Monads[:result]

      def initialize(artifact_repository:, relationship_repository:)
        @artifact_repository = artifact_repository
        @relationship_repository = relationship_repository
      end

      def call(request)
        # 1. Check both artifacts exist
        source = @artifact_repository.find(request.source_id)
        return Failure("Source artifact not found") unless source

        target = @artifact_repository.find(request.target_id)
        return Failure("Target artifact not found") unless target

        # 2. Check they're in the same project
        if source.project_id != target.project_id
          return Failure("Artifacts must be in the same project")
        end

        # 3. Check relationship doesn't already exist
        if @relationship_repository.exists?(source.id, target.id, request.relationship_type)
          return Failure("This relationship already exists")
        end

        # 4. Bundle the request plus prefetched records for Command phase
        Success(LinkContext.new(request: request, source: source, target: target))
      end
    end
  end
end
```

**Command** (with circular dependency detection):
```ruby
module Traceability
  module LinkArtifacts
    class Command
      include Dry::Monads[:result]

      def initialize(relationship_repository:, event_dispatcher:)
        @relationship_repository = relationship_repository
        @event_dispatcher = event_dispatcher
      end

      def call(context)
        request, source, target = context.request, context.source, context.target

        # Check for circular dependencies
        if creates_circular_dependency?(source, target)
          return Failure("This would create a circular dependency")
        end

        # Create relationship
        relationship = @relationship_repository.create(
          source_artifact_id: source.id,
          target_artifact_id: target.id,
          relationship_type: request.relationship_type
        )

        # Emit event for other domains to react
        @event_dispatcher.dispatch(
          ArtifactsLinked.new(
            relationship_id: relationship.id,
            source_id: source.id,
            target_id: target.id,
            relationship_type: request.relationship_type
          )
        )

        Success(relationship)
      end

      private

      def creates_circular_dependency?(source, target)
        # Simple check: if target already links back to source, it's circular
        @relationship_repository.related_to?(target.id, source.id)
      end
    end
  end
end
```

Wiring the two phases together is then a plain `.bind` chain — `Command` receives the
`LinkContext` that `Validate` returned, no separate data channel needed:

```ruby
Validate.new(**deps).call(request)
  .bind { |context| Command.new(**deps).call(context) }
```

## Pattern 3: Operation that Composes Other Operations

**Use when**: One operation needs to call another (e.g., create artifact AND link it to requirement).

```ruby
module Traceability
  module CreateAndLinkArtifact
    class Command
      include Dry::Monads[:result]

      def initialize(create_service:, link_service:)
        @create_service = create_service
        @link_service = link_service
      end

      def call(create_request, link_request)
        # Chain operations using dry-monads' Result#bind
        @create_service.call(create_request)
          .bind { |artifact|
            link_artifact(artifact, link_request)
          }
      end

      private

      def link_artifact(artifact, request)
        link_request = LinkRequest.new(
          source_id: artifact.id,
          target_id: request.target_id,
          relationship_type: request.relationship_type
        )
        @link_service.call(link_request)
      end
    end
  end
end
```

## Pattern 4: Service Entry Point

**Use when**: You need to orchestrate multiple operations or provide a simple API.

For a domain whose Commands subclass `AverisOS::BaseCommand` (see [Pattern
1](#pattern-1-operation-with-simple-validation) above — currently
`authentication`), the service doesn't manually wire `Verify`/`Validate`
itself; `BaseCommand#call` already does that. The service is a thin
per-use-case delegator over a pre-built `Request`:

```ruby
module Authentication
  class AuthenticationService
    def register_user(request)
      RegisterUser::Command.new.call(request)
    end

    def sign_in(request)
      SignIn::Command.new.call(request)
    end
  end
end
```

For a domain that hasn't adopted `AverisOS::BaseCommand` (below,
`traceability`), the service wires the phases together manually:

```ruby
module Traceability
  class TraceabilityService
    def initialize(container:)
      @container = container
    end

    def create_artifact(project_id:, type:, title:, owner_id:)
      request = CreateArtifact::Request.new(
        project_id: project_id,
        type: type,
        title: title,
        owner_id: owner_id
      )

      # Verify
      result = CreateArtifact::Verify.call(request)
      return result if result.failure?

      # Validate
      validate = CreateArtifact::Validate.new(
        project_repository: @container['repositories.project'],
        user_repository: @container['repositories.user']
      )
      result = validate.call(request)
      return result if result.failure?

      # Command — receives whatever Validate's Success wrapped (the request
      # itself, or a bundling Struct if a later phase needs prefetched data,
      # per Pattern 2 above)
      command = CreateArtifact::Command.new(
        artifact_repository: @container['repositories.artifact'],
        event_dispatcher: @container['services.event_dispatcher']
      )
      command.call(result.value!)
    end
  end
end
```

## Pattern 5: Request with Nested Validation

**Use when**: Request has complex nested data structures.

```ruby
module Traceability
  module CreateArtifactBatch
    class Request
      attr_reader :project_id, :artifacts, :link_rules

      def initialize(project_id:, artifacts:, link_rules: [])
        @project_id = project_id
        @artifacts = artifacts.map { |a| ArtifactData.new(**a) }
        @link_rules = link_rules.map { |r| LinkRule.new(**r) }
      end
    end

    class ArtifactData
      attr_reader :type, :title, :description

      def initialize(type:, title:, description: "")
        @type = type
        @title = title
        @description = description
      end
    end

    class LinkRule
      attr_reader :source_index, :target_index, :relationship_type

      def initialize(source_index:, target_index:, relationship_type:)
        @source_index = source_index
        @target_index = target_index
        @relationship_type = relationship_type
      end
    end

    class Verify
      extend Dry::Monads[:result]

      def self.call(request)
        # Check project_id
        return Failure("Project ID is required") if request.project_id.blank?

        # Check artifacts
        return Failure("At least one artifact is required") if request.artifacts.empty?

        # Verify each artifact
        request.artifacts.each_with_index do |artifact, index|
          return Failure("Artifact #{index}: type is required") if artifact.type.blank?
          return Failure("Artifact #{index}: title is required") if artifact.title.blank?
        end

        # Verify link rules reference valid indices
        request.link_rules.each do |rule|
          if rule.source_index >= request.artifacts.length
            return Failure("Link rule: source index out of range")
          end
          if rule.target_index >= request.artifacts.length
            return Failure("Link rule: target index out of range")
          end
        end

        Success(request)
      end
    end
  end
end
```

## Testing the Patterns

### Unit Test (Verify Phase)
```ruby
describe Traceability::CreateArtifact::Verify do
  it "rejects blank title" do
    request = Traceability::CreateArtifact::Request.new(
      project_id: 1,
      type: "requirement",
      title: "",
      owner_id: 1
    )
    result = described_class.call(request)
    expect(result).to be_failure
    expect(result.failure).to include("Title is required")
  end
end
```

### Integration Test (Validate Phase)
```ruby
describe Traceability::CreateArtifact::Validate do
  it "rejects unknown project" do
    request = Traceability::CreateArtifact::Request.new(
      project_id: 99999,
      type: "requirement",
      title: "Test",
      owner_id: 1
    )
    validate = described_class.new(
      project_repository: double(find: nil),
      user_repository: double(find: build(:user))
    )
    result = validate.call(request)
    expect(result).to be_failure
    expect(result.failure).to include("Project not found")
  end
end
```

### End-to-End Test (Full Operation)
```ruby
describe "CreateArtifact Integration" do
  it "creates artifact and emits event" do
    service = Traceability::TraceabilityService.new(container: AverisOS::Container)
    result = service.create_artifact(
      project_id: 1,
      type: "requirement",
      title: "User can login",
      owner_id: 1
    )

    expect(result).to be_success
    expect(Artifact.count).to eq(1)
    # Verify event was dispatched
  end
end
```
