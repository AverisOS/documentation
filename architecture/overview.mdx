# Architecture Overview

AverisOS is built using **Domain-Driven Design** with Rails 7+, dry-rb, and PostgreSQL. This guide covers the technical foundation and key architectural decisions.

## High-Level Architecture

```
┌─────────────────────────────────────────────────────┐
│                    API Layer                        │
│  (Rails Controllers - HTTP Routing & Serialization) │
└──────────────────┬──────────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────────┐
│              Domain Services Layer                  │
│  (Business Logic, Orchestration, Event Dispatch)   │
│                                                     │
│  ├── Traceability (core)                           │
│  ├── Authentication                                │
│  ├── Git Integration                               │
│  ├── Testing                                        │
│  ├── Email                                          │
│  └── ... (future domains)                          │
└──────────────────┬──────────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────────┐
│          Operations Layer (RVVC Pattern)           │
│                                                    │
│  Request → Verify → Validate → Command            │
│  (Input)  (Format) (Semantic) (Execute)           │
└──────────────────┬──────────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────────┐
│            Persistence Layer                        │
│  (Repositories, Models, Database)                  │
│                                                    │
│  ├── Artifacts                                    │
│  ├── Relationships                                │
│  ├── Users                                        │
│  └── ... (domain models)                          │
└─────────────────────────────────────────────────────┘
```

## Layered Architecture

### 1. API Layer (Controllers)

**Responsibility**: HTTP routing and serialization only

```ruby
class ArtifactsController < ApplicationController
  def create
    # Step 1: Parse HTTP request
    request = CreateArtifact::Request.new(
      project_id: params[:project_id],
      type: params[:type],
      title: params[:title],
      description: params[:description],
      owner_id: current_user.id
    )
    
    # Step 2: Call domain service (business logic happens here)
    result = Container['domains.traceability'].create_artifact(request)
    
    # Step 3: Serialize response
    if result.success?
      render json: ArtifactSerializer.new(result.data[:artifact]), status: :created
    else
      render json: { errors: result.error }, status: :unprocessable_entity
    end
  end
end
```

**Guidelines**:
- ✓ Parse HTTP request
- ✓ Call domain service
- ✓ Serialize response
- ❌ No business logic
- ❌ No database queries
- ❌ No validation

### 2. Domain Services Layer

**Responsibility**: Business logic, orchestration, event dispatch

```ruby
module Traceability
  class TraceabilityService
    def initialize(container:)
      @container = container
    end
    
    def create_artifact(request)
      # Orchestrate Request → Verify → Validate → Command
      result = CreateArtifact::Verify.call(request)
      return result if result.failure?
      
      result = CreateArtifact::Validate.new(repositories).call(request)
      return result if result.failure?
      
      result = CreateArtifact::Command.new(repositories, @container['services.event_dispatcher']).call(request, result.data)
      result
    end
  end
end
```

**Guidelines**:
- ✓ Orchestrate operations
- ✓ Emit domain events
- ✓ Manage transactions
- ✓ Handle cross-domain communication
- ❌ No HTTP concerns
- ❌ No low-level validation

### 3. Operations Layer (RVVC Pattern)

**Responsibility**: Structured request processing through four phases

Each operation has four classes:

**Request** (Input definition)
```ruby
class CreateArtifact::Request
  attr_reader :project_id, :type, :title, :description, :owner_id
  
  def initialize(project_id:, type:, title:, description: nil, owner_id:)
    @project_id = project_id
    @type = type
    @title = title
    @description = description
    @owner_id = owner_id
  end
end
```

**Verify** (Format validation - no database)
```ruby
class CreateArtifact::Verify
  VALID_TYPES = %w[requirement feature code test release].freeze
  
  def self.call(request)
    errors = []
    errors << "project_id required" if request.project_id.blank?
    errors << "type required" if request.type.blank?
    errors << "type must be one of: #{VALID_TYPES.join(', ')}" unless VALID_TYPES.include?(request.type)
    errors << "title required" if request.title.blank?
    errors << "title max 500 chars" if request.title.to_s.length > 500
    
    return Shared::Result.failure(errors.join("; ")) if errors.any?
    Shared::Result.success(request)
  end
end
```

**Validate** (Semantic validation - with database)
```ruby
class CreateArtifact::Validate
  def initialize(repositories)
    @repositories = repositories
  end
  
  def call(request)
    # Check business rules
    project = @repositories[:project].find(request.project_id)
    return Shared::Result.failure("Project not found") unless project
    
    owner = @repositories[:user].find(request.owner_id)
    return Shared::Result.failure("Owner not found") unless owner
    
    # Prefetch data for Command phase
    data = {
      project: project,
      owner: owner
    }
    
    Shared::Result.success(request, data: data)
  end
end
```

**Command** (Execution - side effects)
```ruby
class CreateArtifact::Command
  def initialize(repositories, event_dispatcher)
    @repositories = repositories
    @event_dispatcher = event_dispatcher
  end
  
  def call(request, prefetched_data)
    # Create artifact
    artifact = @repositories[:artifact].create(
      project_id: request.project_id,
      type: request.type,
      title: request.title,
      description: request.description,
      owner_id: request.owner_id,
      status: 'draft'
    )
    
    # Emit event for other domains to subscribe to
    @event_dispatcher.dispatch(
      ArtifactCreated.new(artifact_id: artifact.id, project_id: artifact.project_id)
    )
    
    Shared::Result.success({ artifact: artifact })
  end
end
```

### 4. Persistence Layer (Models & Repositories)

**Models** (Thin - associations and validations only)
```ruby
class Artifact < ApplicationRecord
  belongs_to :project
  belongs_to :owner, class_name: 'User'
  has_many :relationships_as_source, class_name: 'ArtifactRelationship', foreign_key: :source_id
  has_many :relationships_as_target, class_name: 'ArtifactRelationship', foreign_key: :target_id
  
  validates :type, inclusion: { in: %w[requirement feature code test release] }
  validates :title, presence: true, length: { maximum: 500 }
end
```

**Repositories** (Data access abstraction)
```ruby
class ArtifactRepository
  def create(attributes)
    Artifact.create!(attributes)
  end
  
  def find(id)
    Artifact.find_by(id: id)
  end
  
  def find_related(artifact_id, relationship_type)
    # Find all artifacts connected to this one
    Artifact
      .joins(:relationships_as_source)
      .where(artifact_relationships: { source_id: artifact_id, type: relationship_type })
  end
end
```

## Key Patterns

### 1. Result Monad

All operations return `Success` or `Failure`, never raise exceptions for expected errors:

```ruby
class CreateArtifact::Verify
  def self.call(request)
    # Success case
    Shared::Result.success(request)
    
    # Failure case
    Shared::Result.failure("title required")
  end
end

# Usage
result = CreateArtifact::Verify.call(request)
if result.success?
  puts "Created: #{result.data}"
else
  puts "Error: #{result.error}"
end

# Composition
result = CreateArtifact::Verify.call(request)
  .and_then { |req| CreateArtifact::Validate.call(req) }
  .and_then { |req| CreateArtifact::Command.call(req) }
```

### 2. Dependency Injection

All dependencies injected via dry-container, never hardcoded:

```ruby
# In config/initializers/container.rb
Container.register('domains.traceability') do
  Traceability::TraceabilityService.new(container: Container)
end

Container.register('repositories.artifact') do
  ArtifactRepository.new
end

# In controllers
service = Container['domains.traceability']
service.create_artifact(request)
```

### 3. Event-Driven Communication

Domains emit events, other domains subscribe:

```ruby
# Traceability domain emits event
@event_dispatcher.dispatch(ArtifactCreated.new(artifact_id: artifact.id))

# Email domain subscribes
# In config/initializers/event_subscriptions.rb
event_dispatcher.subscribe(Traceability::ArtifactCreated) do |event|
  # Send notification
  Email::SendArtifactCreatedNotification.call(event.artifact_id)
end
```

## Communication Between Layers

### Request Flow

```
HTTP Request
  ↓
[Controller]
  ├─ Parse request params
  ├─ Create Request object
  └─ Call domain service
      ↓
    [Domain Service]
      ├─ Orchestrate Verify
      ├─ Orchestrate Validate
      ├─ Orchestrate Command
      └─ Emit events
          ↓
        [Verify] No database
        [Validate] Database queries
        [Command] Database writes + events
              ↓
            [Event Dispatcher]
              ├─ Email subscribes
              ├─ Git subscribes
              └─ Testing subscribes
  ↓
[Serializer]
  ├─ Format response
  └─ Return JSON
      ↓
HTTP Response
```

### Domain Communication (Loose Coupling)

```
❌ WRONG: Direct dependency
Traceability::CreateArtifact::Command
  └─ Email::SendNotification.call()  # Tight coupling

✓ RIGHT: Event-driven
Traceability::CreateArtifact::Command
  └─ @event_dispatcher.dispatch(ArtifactCreated)
      ↓
    [Event Subscribers]
      └─ Email::SendArtifactCreatedNotification.call()
```

## Database Schema

Core entities:

```sql
-- Artifacts (requirements, features, code, tests, releases)
CREATE TABLE artifacts (
  id BIGINT PRIMARY KEY,
  project_id BIGINT NOT NULL,
  type VARCHAR(50),  -- 'requirement', 'feature', 'code', 'test', 'release'

  description TEXT,
  owner_id BIGINT,

  created_at TIMESTAMP,
  updated_at TIMESTAMP

CREATE TABLE users (
  id BIGINT PRIMARY KEY,
  email VARCHAR(255),
  encrypted_password VARCHAR(255),
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);

CREATE TABLE projects (
  id BIGINT PRIMARY KEY,
  name VARCHAR(255),
  owner_id BIGINT,
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);
```

## Key Architectural Principles

1. **Business Logic First**: Domain services contain all business logic, never in models
2. **Clear Phases**: Every operation goes through Verify → Validate → Command for clarity
3. **Explicit Errors**: Result monad makes error paths visible and testable
4. **Loose Coupling**: Event-driven communication between domains, not direct calls
5. **Dependency Injection**: All dependencies injected, never hardcoded
6. **Thin Models**: Models do associations and validations only
7. **Repository Pattern**: Data access abstracted from business logic

## Scaling Considerations

### Phase 1-2: Monorepo
All domains in one Rails app. Fast development, shared code, easy cross-domain changes.

### Phase 3+: Microservices
Extract high-traffic domains to separate services:
- Traceability service (high read volume)
- Git integration service (webhook processing)
- Email service (async, high volume)
- Keep auth service co-located
