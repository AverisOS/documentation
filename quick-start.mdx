# Quick Start Guide

New to AverisOS? This 5-minute guide will get you oriented.

## 1. Understand the Problem (1 min)

AverisOS solves **fragmentation** in software delivery:

- Teams use 10-30+ disconnected tools
- Context is lost between decisions and code
- Impact analysis is manual
- AI can't help without understanding your system

**Solution:** A unified platform where artifacts (requirements, code, tests) are connected.

## 2. Know the Vision (1 min)

Build an **operating system for software delivery** where teams can answer:

- ✅ What are we building and why?
- ✅ What decisions shaped this?
- ✅ What code implements this?
- ✅ What tests validate this?
- ✅ Is it safe to release?
- ✅ Did it create value?

## 3. See the Plan (1 min)

We're building in **3 phases over 18 months**:

### Phase 1: Core MVP (Months 1-3)
- Build traceability graph
- Git integration
- Basic CLI and IDE plugin
- Validate with design partners

### Phase 2: Market Fit (Months 4-8)
- Add AI agents
- Advanced traceability
- Sales and pricing
- 10-20 paying customers

### Phase 3: Enterprise Scale (Months 9-18)
- Enterprise features
- Multi-region
- Marketplace
- 50+ customers

**See:** [Roadmap](/planning/roadmap) for full details

## 4. Learn the Architecture (2 min)

We're building in **Rails + Domain-Driven Design**:

**Key Principle:** Business logic is first-class citizen

```
HTTP Layer (Controllers)
    ↓
Domain Services (Orchestration)
    ↓
Domain Operations (Business Logic) ← HERE
    ↓
Models (Persistence)
```

**Core Pattern:** Every operation has 4 phases:
1. **Request** — Input parameters
2. **Verify** — Format/syntax validation (no DB)
3. **Validate** — Semantic validation (with DB)
4. **Command** — Execute (emit events)

**Error Handling:** Result monad (success/failure), not exceptions

**See:** [Architecture Overview](/architecture/overview)

## Key Concepts

| Term | Meaning |
|------|---------|
| **Artifact** | Any unit of work: requirement, feature, code, test, release |
| **Relationship** | Connection between artifacts (implements, validates, depends_on) |
| **Traceability** | Ability to trace requirements → code → tests → releases |
| **Domain** | Self-contained bounded context (Authentication, Traceability, etc.) |
| **Operation** | Business logic unit (CreateArtifact, LinkArtifacts, etc.) |
