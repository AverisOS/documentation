# ADR-008: Open-Source Core Components (CLI, SDKs)

**Date**: September 2026  
**Status**: ✅ Accepted  
**Author**: Aaron

---

## Context

Should we open-source parts of AverisOS or keep everything proprietary?

### Options

**1. Proprietary Everything**
- Keep all code private
- No community input
- Full control

**2. Open-Source Everything**
- Community can contribute
- Transparency
- Risk of competitors forking

**3. Hybrid (This Decision)**
- Open-source CLI and SDKs
- Keep backend proprietary
- Community can build integrations
- Customers own their CLI

---

## Decision

**Open-source in Phase 2+**:

- ✓ **CLI tool**: Open-source (helps adoption, community contributions)
- ✓ **SDKs**: Open-source (Ruby, Python, JavaScript)
- ❌ **Server/backend**: Keep proprietary (contains business logic)

### Why This Mix?
- **CLI**: Users can audit, extend, contribute
- **SDKs**: Integrate easily in their stacks
- **Server**: Where the value is (traceability engine, AI)

---

## Alternatives Considered

### 1. All Proprietary
**Pros**: Control, can charge for everything  
**Cons**: No community, slower adoption, limited integrations

**Verdict**: Limits growth.

### 2. All Open-Source
**Pros**: Maximum transparency, community contributions  
**Cons**: Competitors can fork, no direct revenue from core

**Verdict**: Too generous.

### 3. Hybrid (This Decision)
**Pros**: Community benefits, integrations, adoption; we keep core  
**Cons**: Slight maintenance overhead for open-source projects

**Verdict**: Best balance.

---

## Rationale

### ✓ Adoption
Open-source CLI increases adoption:
- Early adopters can self-serve
- No vendor lock-in fear
- Community discovers the tool
- Word of mouth spreads faster

### ✓ Network Effects
More people using CLI → more people discover AverisOS → more SaaS customers:
```
Open-source CLI
    ↓
1000 developers using CLI
    ↓
100 of them evaluate SaaS
    ↓
10 become paying customers
    ↓
Company revenue
```

### ✓ Talent
Open-source attracts engineers:
- Engineers want to work on open-source
- Resume building (portfolio piece)
- Community contributions signal quality

### ✓ Lock-In Prevention
Shows we're not locking customers in:
- Customers can use open-source CLI with any backend
- If they leave our SaaS, CLI still works
- Builds trust

### ✓ Community Integrations
Developers build on our open APIs:
- GitHub Actions (run AverisOS in CI)
- Slack bot (get traceability in Slack)
- VS Code extension (view artifacts in editor)
- IDE integrations (JetBrains plugins)

We don't build these; community does.

---

## Consequences

### ✅ Positive
- **Faster adoption**: Open-source removes barrier
- **Community contributions**: CLI improvements, bug fixes
- **Network effects**: CLI users become SaaS leads
- **Trust**: Transparent tooling builds confidence
- **Integrations**: Community extends via open APIs

### ⚠️ Negative
- **Maintenance**: Need to manage open-source projects
- **Can't charge for CLI**: Revenue from SaaS only
- **Support burden**: More people asking for help
- **Security reviews**: Public code gets scrutinized
- **Competitors**: Can review source code

### 🛡️ Mitigation
- **Sponsor community developers** (Fund key contributors)
- **Clear governance**: Document decision-making
- **Security policy**: Responsible disclosure
- **Support channels**: Don't support everything (prioritize paying customers)

## Revenue Model with Open-Source

**Free tier** (open-source CLI):
- Self-hosted traceability
- Local artifact tracking
- No cloud
- No collaboration

**Paid tier** (AverisOS SaaS):
- Cloud-hosted traceability
- Team collaboration
- AI-enhanced linking (Phase 2+)
- Integrations and webhooks
- Analytics and reporting
- Professional support

Revenue sources:
1. **SaaS subscriptions** (primary)
2. **Professional services** (implementation, training)
3. **Support contracts** (enterprise)
4. **Data services** (optional: anonymized insights)

## Example: GitHub Action Integration

Community builds (not us):

```yaml
# .github/workflows/traceability.yml
- name: Link commits to requirements
  uses: averis-os/github-action@v1
  with:
    project-id: ${{ secrets.AVERIS_PROJECT_ID }}
    api-url: https://api.averis-os.com
```

This brings AverisOS into user CI/CD pipelines.
